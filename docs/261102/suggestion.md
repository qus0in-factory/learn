# 강의안 조정 제안

## Why

초안은 현재 자료보다 운영안이 구체적이지만, 세 가지 진행안과 도구·활동 설명이 더해져 강의 순서가 달라지고 범위가 넓어졌습니다. 현재 자료는 A 첫 커밋 → B GitHub 공유 → C 페이지 개인화 → D 협업 맛보기 순이며, Markdown은 README 안내에만 포함되어 있습니다.

## What

초안의 세 안 중 하나를 새로 채택하기보다, 원래 순서를 **Git → Markdown → Branch**으로 두고 필요한 운영 보강만 반영하는 안을 제안합니다.

| 블록 | 내용 및 순서 | 실습·퀴즈 |
| --- | --- | --- |
| 첫 번째 3시간 | Git 기초: 작업 폴더·스테이징·커밋, `status`·`add`·`commit`·`log` | 제목 변경 후 커밋; `add` 전후 상태와 Git/GitHub 차이 확인 |
| 두 번째 3시간 | Git 공유: 원격 저장소, `push`, Pages 배포·변경 확인 | 문구 변경 후 커밋·push; commit/push 차이와 확인 위치 질문 |
| 세 번째 3시간 | Markdown: 기본 문법, README, Issue와 TIL 소개 | README에 소개와 배포 링크 추가; Markdown의 용도 확인 |
| 네 번째 3시간 | Branch: 브랜치, 병합과 PR 흐름 | 작은 변경을 브랜치에서 진행; PR의 목적 확인 |

각 블록은 기존 운영 조건대로 45분 수업과 15분 휴식 3회로 구성하고, 세 번째 수업의 마지막 20분을 실습 15분과 퀴즈 5분으로 둡니다. 일정이 밀리면 PR은 강사 시연으로 전환하고, Git 기록·원격 공유·Pages 확인을 우선합니다.

## How

- **사전 준비:** 첫 시간에 Git·VS Code·OpenCode 설치를 시작하고, 진행 중 PPT로 VCS와 스테이징 등 기본 개념을 설명합니다. GitHub 로그인·인증과 Pages 사용 가능 여부도 확인합니다. 설치 권한이나 조직 계정 제약이 예상되면 강사용 예제 저장소와 웹 화면 시연을 준비합니다.
- **학습자 고려:** Python 기초를 배운 초보자를 기준으로 명령을 한 줄씩 안내하고, 매 변경마다 브라우저·변경 파일·`git status`를 함께 확인합니다. 막히면 강사 시연이나 짝 활동으로 이어가되 학습자가 자신의 커밋 결과를 확인하게 합니다.
- **원안 유지:** Git과 GitHub의 구분, 로컬 변경 확인 후 기록, 원격 공유와 배포라는 성과는 유지합니다. 명령 세부와 기존 A/B/C/D 자료는 실제 강의 자료를 고칠 때까지 그대로 둡니다.
- **초안 중 보류:** 안 1·2·3의 별도 일정안, 폰트·파비콘·Coolors 중심의 개인화 확장은 Markdown 이후 선택 활동으로, `gh`와 ChatGPT 연결은 해당 항목에서 짧게 소개하는 안을 제안합니다. 필요하면 강의 후 선택 활동으로 다룹니다.

이 문서는 검토 제안이며 실제 슬라이드·강의 문서·README에는 변경을 반영하지 않았습니다.
