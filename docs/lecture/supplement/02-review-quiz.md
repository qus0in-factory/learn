# 보충 2. 복습용 퀴즈

본 과정에서 배운 Git 흐름을 스스로 점검하는 10문항입니다. 정답 확인보다 개념 연결을 목표로 합니다. 정답을 모르면 해당 차시와 부록을 다시 읽습니다. 남은 시간에 따라 3문항, 6문항, 10문항 중에서 고릅니다.

## 이 파트에서 하는 일

- 본 과정에서 배운 Git 흐름을 학습자가 스스로 점검합니다.
- 정답 확인보다 개념 연결을 목표로 합니다.

## 왜 필요한가

명령을 한 번 따라 했다고 해서 개념이 머리에 남는 것은 아닙니다. 질문을 보고 직접 설명해 보면 어디에서 헷갈리는지 빨리 찾을 수 있습니다. 이 퀴즈는 다시 읽어야 할 차시를 고르기 위한 도구입니다.

## 시간별 진입 조건

- **15분:** 3문항만 구두로 확인합니다.
- **30분:** 6문항을 풀고 해설을 확인합니다.
- **60분:** 10문항을 풀고 해설을 확인합니다.

## 문항

1. `git status`는 무엇을 보여주는가?
2. `git add` 전후 상태는 어떻게 달라지는가?
3. 커밋과 `push`는 무엇이 다른가?
4. Git과 GitHub는 각각 무엇을 하는가?
5. Markdown은 어디에 쓰는가?
6. Issue와 Wiki는 어떤 기록에 적합한가?
7. 브랜치와 tag는 어떻게 다른가?
8. PR은 무엇을 제안하는가?
9. 충돌은 언제 생기는가?
10. Pages 변경 반영은 어디서 확인하는가?

## 해설

| 번호 | 해설 | 다시 보기 |
| :---: | :--- | :--- |
| 1 | 현재 변경 파일과 스테이징 상태를 보여준다. | [2차시](../02-local-repository.md) |
| 2 | `add` 전에는 untracked/modified, 후에는 staged로 바뀐다. | [2차시](../02-local-repository.md) |
| 3 | commit은 로컬 기록, push는 원격 공유다. | [5차시](../05-remote.md) |
| 4 | Git은 로컬 버전 관리, GitHub는 원격 저장소와 협업 서비스다. | [5차시](../05-remote.md) |
| 5 | README, TIL, 회고, Issue 설명 등 문서 작성에 쓴다. | [7차시](../07-markdown-mermaid.md) |
| 6 | Issue는 작업 요청과 개선점, Wiki는 프로젝트 지식베이스에 적합하다. | [8차시](../08-profile-records.md) · [9차시](../09-issues.md) |
| 7 | 브랜치는 작업 흐름, tag는 릴리스 지점이다. | [10차시](../10-branches-tags.md) |
| 8 | 브랜치 변경을 기본 브랜치에 반영해 달라고 제안한다. | [12차시](../12-pull-request.md) |
| 9 | 같은 파일의 같은 줄을 다르게 수정했을 때 생긴다. | [11차시](../11-merge-conflicts.md) |
| 10 | GitHub Pages URL과 저장소 Actions/Pages 상태에서 확인한다. | [6차시](../06-pages.md) |
