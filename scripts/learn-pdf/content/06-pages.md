# 웹사이트 배포
교안: [STEP 06 §학습 목표](https://echo.qus0in.dev/git/06-pages#학습-목표)

- 정적 파일을 공개 주소로 제공한다.
- 브랜치와 폴더를 저장한 뒤 배포 완료를 확인한다.
- 공개 페이지에 민감 정보를 올리지 않는다.

## 공개의 목적
교안: [STEP 06 §정적 웹 배포의 목적](https://echo.qus0in.dev/git/06-pages#정적-웹-배포의-목적)

- 로컬 파일 경로는 그 컴퓨터에서만 열린다.
- 정적 웹은 준비된 파일을 그대로 제공한다.
- push 뒤 사이트가 갱신되는 흐름이 배포의 기본이다.

## 링크 미리보기
교안: [STEP 06 §링크 미리보기](https://echo.qus0in.dev/git/06-pages#링크-미리보기)

- 링크를 공유하면 제목, 설명, 이미지가 먼저 보일 수 있다.
- 그 값은 페이지 정보에 두고, 작성 예시는 교안에서 확인한다.
- 서비스가 이전 미리보기를 잠시 보여줄 수 있다.

## 배포 흐름
교안: [STEP 06 §호스팅 원리와 자동 재배포](https://echo.qus0in.dev/git/06-pages#호스팅-원리와-자동-재배포)

1. 로컬에서 고친 내용을 커밋한다.
2. 지정한 브랜치로 push한다.
3. 원격 자동화가 사이트를 다시 배포한다.
4. 첫 화면 파일 이름은 소문자 index.html이어야 한다.

## 설정 순서
교안: [STEP 06 §따라하기](https://echo.qus0in.dev/git/06-pages#따라하기)

1. 저장소 설정에서 Pages를 연다.
2. 배포 원본은 브랜치 배포를 유지한다.
3. 브랜치는 main, 폴더는 루트로 저장한다.
4. 안내 주소가 나오면 첫 화면이 열리는지 확인한다.

## 확인 기준
교안: [STEP 06 §체크리스트](https://echo.qus0in.dev/git/06-pages#체크리스트)

1. Pages의 브랜치와 폴더가 저장되었는지 확인한다.
2. 공개 주소에서 첫 화면이 열리는지 확인한다.
3. 수정 후 push하면 배포 작업이 성공하는지 확인한다.
4. 갱신이 안 보이면 교안의 대응표로 원인을 가른다.

## 공개 전 확인
교안: [STEP 06 §주의할 점](https://echo.qus0in.dev/git/06-pages#주의할-점)

- 연락처, 주소, 내부 자료를 공개 페이지에 올리지 않는다.
- 글꼴은 사용 범위를 확인한 뒤 가져온다.
- 미리보기 캐시와 도구 안내는 교안에서 확인한다.
