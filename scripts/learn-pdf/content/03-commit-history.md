# 커밋과 이력 기록
교안: [STEP 03 §학습 목표](https://echo.qus0in.dev/git/03-commit-history#학습-목표)

- 선택한 변경을 커밋으로 기록한다.
- 변경 내용과 커밋 이력을 확인한다.
- 잘못 선택한 변경은 스테이징에서 내린다.

## 작업 단위로 기록
교안: [STEP 03 §왜 작업 단위로 기록할까](https://echo.qus0in.dev/git/03-commit-history#왜-작업-단위로-기록할까)

- 커밋은 의미 있는 작업 단위의 스냅샷이다.
- 기록은 변경을 살펴보고 이전 상태를 찾는 기준이 된다.
- 메시지에 무엇을 왜 바꿨는지 담는다.

## 해시와 메시지
교안: [STEP 03 §커밋 스냅샷과 해시의 원리](https://echo.qus0in.dev/git/03-commit-history#커밋-스냅샷과-해시의-원리)

- 각 커밋은 해시로 구분하며 앞선 커밋과 연결된다.
- 짧은 해시를 사용할 때는 저장소에서 유일한지 확인한다.
- 메시지 제목은 한 줄로 요약하고 필요하면 이유를 덧붙인다.

## 첫 기록과 수정
교안: [STEP 03 §따라하기](https://echo.qus0in.dev/git/03-commit-history#따라하기)

- 준비된 변경을 첫 커밋으로 기록하고 이력을 확인한다.
- 파일을 수정해 저장한 뒤 변경 상태를 살펴본다.
- 기록 전 실제 변경 내용을 비교한다.

## 선택을 고치고 기록
교안: [STEP 03 §따라하기](https://echo.qus0in.dev/git/03-commit-history#따라하기)

- 수정한 변경을 스테이징한다.
- 잘못 선택했다면 스테이징에서 내리고 상태를 확인한다.
- 다시 선택한 뒤 두 번째 커밋을 만든다.

## 이력과 완료 확인
교안: [STEP 03 §체크리스트](https://echo.qus0in.dev/git/03-commit-history#체크리스트)

- 두 커밋의 해시와 메시지를 확인한다.
- 작업 트리가 깨끗한지 확인한다.
- 변경 비교와 기본 편집기 종료 방법을 확인한다.

## 변경 비교의 범위
교안: [STEP 03 §트러블 슈팅](https://echo.qus0in.dev/git/03-commit-history#트러블-슈팅)

- 작업 공간의 변경과 스테이징된 변경은 따로 살펴본다.
- 변경 비교 결과가 비었다면 스테이징 상태를 확인한다.
- 편집기가 열리면 교안의 저장·종료 안내를 따른다.
