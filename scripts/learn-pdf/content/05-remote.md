# 원격 저장소와 동기화
교안: [STEP 05 §학습 목표](https://echo.qus0in.dev/git/05-remote#학습-목표)

- 로컬 저장소를 원격 저장소와 연결한다.
- 첫 공유 전에 브랜치 이름과 빈 저장소 여부를 확인한다.
- 인증 값과 원격 이력을 덮어쓰는 방법을 경계한다.

## 원격이 필요한 이유
교안: [STEP 05 §클라우드 협업이 필요한 이유](https://echo.qus0in.dev/git/05-remote#클라우드-협업이-필요한-이유)

- 로컬 이력만 있으면 기기 문제 때 작업을 잃을 수 있다.
- 원격 호스팅은 백업과 함께 작업할 기준점이 된다.
- 다음 공개 배포는 이 원격 저장소를 바탕으로 한다.

## 연결 순서
교안: [STEP 05 §따라하기](https://echo.qus0in.dev/git/05-remote#따라하기)

1. 로컬에 파일이 있으면 초기 파일 없는 빈 저장소로 만든다.
2. 브랜치 이름을 확인하고, main이 아니면 변경 가능 여부를 먼저 판단한다.
3. origin에 원격 주소를 등록하고 주소가 맞는지 확인한다.
4. 첫 push에서 로컬 main과 원격 main을 기본 연결로 등록한다.
5. 원격 페이지에 파일과 이력이 보이는지 확인한다.

## 주고받는 방향
교안: [STEP 05 §원격 연결과 동기화 메커니즘](https://echo.qus0in.dev/git/05-remote#원격-연결과-동기화-메커니즘)

| 동작 | 방향 | 언제 |
| --- | --- | --- |
| clone | 원격 이력을 로컬로 복제 | 새 작업 위치를 만들 때 |
| pull | 원격의 새 커밋을 로컬에 병합 | 연결된 브랜치를 맞출 때 |
| fork | 다른 저장소를 내 원격으로 복사 | 기여용 복사본이 필요할 때 |
| push | 로컬 커밋을 원격에 반영 | 공유할 기록이 있을 때 |

## 인증 경계
교안: [STEP 05 §인증 준비](https://echo.qus0in.dev/git/05-remote#인증-준비)

- 첫 push는 브라우저 로그인으로 인증한다.
- 비밀번호와 토큰을 명령, 소스, 이슈에 적지 않는다.
- 다른 계정 자격이 남아 있으면 교안의 재인증 안내를 따른다.
- 강제 push로 원격 이력을 덮어쓰지 않는다.

## 완료 기준
교안: [STEP 05 §체크리스트](https://echo.qus0in.dev/git/05-remote#체크리스트)

1. origin의 받기·올리기 주소가 의도한 저장소인지 확인한다.
2. 브랜치 이름을 실습 기준에 맞췄는지 확인한다.
3. 첫 push가 오류 없이 끝났는지 확인한다.
4. 원격 페이지와 로컬 상태가 같은 이력을 가리키는지 확인한다.
