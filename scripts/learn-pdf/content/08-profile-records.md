# 프로필과 작업 기록
교안: [STEP 08 §학습 목표](https://echo.qus0in.dev/git/08-profile-records#학습-목표)

- Profile 저장소와 작업 저장소를 구분한다.
- 사후분석 문서를 만들어 반영한다.
- 기록의 종류와 작성 틀을 구분해 고른다.

## 기록이 필요한 이유
교안: [STEP 08 §왜 필요한가](https://echo.qus0in.dev/git/08-profile-records#왜-필요한가)

- 배운 내용은 다시 찾아볼 일이 생긴다.
- 해결 과정을 남기면 같은 문제에 참고할 수 있다.

## 저장소 역할
교안: [STEP 08 §저장소 역할 구분](https://echo.qus0in.dev/git/08-profile-records#저장소-역할-구분)

| 저장소 | 역할 |
| --- | --- |
| Profile (사용자명과 동일 이름) | README가 프로필 첫 화면에 표시 |
| 개인 사이트 (사용자명.github.io) | Pages로 블로그·이력서 게시 |
| 작업 저장소 | 코드와 문서 보관 |

## 기록 종류 × 작성 틀
교안: [STEP 08 §기록 종류와 작성 틀](https://echo.qus0in.dev/git/08-profile-records#기록-종류와-작성-틀)

- 종류는 글의 목적이고, 틀은 내용을 배열하는 방법이다.
- 두 축은 독립적이며 상황에 맞는 틀을 고른다.

| 종류 | 목적 | 틀 예 |
| --- | --- | --- |
| TIL | 배운 점 남기기 | Why→What→How, STAR |
| 회고 | 다음 행동 정하기 | KPT, 4F |
| 부검 | 원인·재발 방지 | STAR, Why→What→How |

## 회고와 부검의 기준
교안: [STEP 08 §부검](https://echo.qus0in.dev/git/08-profile-records#부검)

- 회고: 유지할 점, 어려웠던 점, 다음 시도를 나눈다.
- 부검: 현상과 영향을 먼저 쓰고 근거로 원인·조치·재발 방지를 구분한다.
- 사람 탓이 아니라 재발 조건과 절차 개선을 찾는다.

## 작업 순서
교안: [STEP 08 §따라하기](https://echo.qus0in.dev/git/08-profile-records#따라하기)

1. 작업 저장소 위치를 확인한다.
2. 사용자명과 같은 공개 Profile 저장소를 만들어 README를 쓴다.
3. 작업 저장소에 사후분석 문서를 만들고 커밋·푸시한다.
4. Wiki를 만들거나 대체 문서 위치를 정한다.

## 완료 기준
교안: [STEP 08 §체크리스트](https://echo.qus0in.dev/git/08-profile-records#체크리스트)

- 프로필에 소개 카드가 표시된다.
- 사후분석 문서가 작업 저장소에 있다.
- 두 저장소의 역할을 구분해 말할 수 있다.

## 주의할 점
교안: [STEP 08 §주의할 점](https://echo.qus0in.dev/git/08-profile-records#주의할-점)

- 공개 프로필에 개인 정보를 과도하게 적지 않는다.
- 기록에 비밀 값, 토큰, 비밀번호를 적지 않는다.
- 프로필 README와 프로젝트 문서는 각 저장소에서 커밋한다.
