# Git 중심 형상관리와 코딩 에이전트 활용

> Python 기초를 익힌 초보자가 작은 웹페이지를 만들고, 변경을 확인해 Git으로 기록한 뒤 GitHub에 공유하는 실습형 수업입니다.

## 수업 목표

- 작업 폴더, 스테이징, 커밋, 원격 저장소의 역할을 설명합니다.
- 에이전트가 바꾼 파일을 브라우저와 변경 내용으로 확인합니다.
- `git status`를 읽고 변경을 커밋한 뒤 GitHub에 push합니다.
- 공개 정책에 맞춰 GitHub Pages 결과를 확인합니다.

## 진행 방식

2일 과정으로 계획했지만 주제를 날짜와 시간표에 고정하지 않습니다. 설치와 인증이 원활하면 다음 실습으로 넘어가고, 막힌 부분은 준비·질문 시간에 해결합니다. 이미 준비된 학습자는 개인화 실습을 먼저 할 수 있습니다. 각 3시간 단위에는 직접 해보는 과제와 확인 퀴즈를 둡니다.

| 블록 | 다루는 주제 | 실습 과제 | 마무리 퀴즈 |
| --- | --- | --- | --- |
| A. 시작과 첫 기록 | Git·GitHub 구분, 프로젝트 폴더, 에이전트로 작은 문구 수정, `init`·`status`·`add`·`commit` | 제목을 자신의 문구로 바꾸고 커밋 | `add` 전후 상태와 Git/GitHub 차이 설명 |
| B. 원격 공유 | 저장소 만들기, 원격 연결, `push`, Pages 확인 | 변경을 다시 커밋·push하고 GitHub에서 확인 | commit과 push 차이, 확인 위치 말하기 |
| C. 나만의 페이지 | 폰트·색·소개, 이용 조건, 작은 요청과 확인 | 선택한 부분을 바꾸고 커밋·push | 외부 리소스 사용 전 확인점과 파일 검토 방법 |
| D. 협업 맛보기 | 브랜치·Pull Request, 짝 리뷰, 선택적 `gh` 시연 | 다른 사람의 변경을 읽고 한 줄 피드백 | PR 용도와 웹 화면으로도 가능한 활동 말하기 |

강사는 학습자의 준비도와 질문에 따라 블록을 재배치합니다. 설치·인증 문제가 생기면 웹 화면 시연과 짝 활동으로 이어가며 로컬 커밋과 변경 이해를 우선합니다.

## 도구의 역할

| 도구 | 하는 일 | 수업에서의 기준 |
| --- | --- | --- |
| Git | 로컬 변경 이력 기록 | 명령을 한 줄씩 실행하고 `status`를 확인 |
| GitHub | 원격 저장, 공유, 이슈·PR, Pages | 웹 화면으로 저장소와 결과 확인 |
| OpenCode 등 코딩 에이전트 | 요청에 따라 로컬 파일을 읽고 수정 | 작은 요청을 주고 파일·브라우저 결과를 검토 |
| GitHub CLI `gh` | 터미널에서 GitHub 서비스 작업 | 선택 시연. 설치·인증이 안 되어도 수업 진행 |
| ChatGPT GitHub 연결 | 허용된 저장소 내용을 검색·질의 | 계정·조직 정책에 따른 선택 기능. 필수 아님 |

Git은 로컬 기록을 다루고 GitHub CLI는 GitHub 서비스 작업을 보완합니다. ChatGPT의 GitHub 연결은 저장소 내용을 찾아 답하는 기능으로, 코딩 에이전트처럼 로컬 코드를 바꾸는 도구와 다릅니다. 제품 화면과 이용 가능성은 계정·요금제·조직 정책에 따라 달라질 수 있습니다. 토큰, 비밀번호, 개인 코드를 채팅에 붙이지 않습니다.

## 한 번의 변경 흐름

```mermaid
flowchart LR
  W[작업 폴더] -->|git add| S[기록할 변경 고르기]
  S -->|git commit| L[로컬 기록]
  L <-->|push / pull| R[GitHub 저장소]
  A[에이전트] -->|파일 수정| W
  R --> P[Pages 결과 확인]
```

먼저 현재 위치를 확인하고 저장소 폴더 안에서 실행합니다.

```bash
git status
git add index.html style.css
git status
git commit -m "소개 문구 수정"
git log --oneline
git push
```

`add`는 다음 기록에 포함할 변경을 고릅니다. `commit`은 내 컴퓨터에 기록하고, `push`는 그 기록을 원격 저장소에 보냅니다. 실제 파일 이름과 원격 설정은 강사 안내를 따릅니다.

## 에이전트에게 요청하기

요청은 작고 구체적으로 합니다. 바꿀 파일과 원하는 결과를 말하고, 수정 뒤에는 브라우저와 변경 내용을 확인합니다.

> `index.html`의 소개 문구를 “안녕하세요, 저의 첫 웹페이지입니다”로 바꿔줘. 다른 파일은 수정하지 말고, 변경 파일과 내용을 알려줘.

## 모바일 화면

페이지와 설명은 320px 너비에서도 읽을 수 있도록 긴 문단을 나누고, 표와 명령은 필요한 만큼만 둡니다. 다이어그램이 좁은 화면에서 작아지면 문장 설명을 함께 읽거나 가로로 이동해 확인합니다.

## 준비와 안전

- Windows PC, 인터넷, Git, VS Code, 선정한 코딩 에이전트 설치 권한을 확인합니다.
- GitHub 계정의 이메일 인증과 조직 저장소 정책을 확인합니다.
- Pages의 공개 범위와 요금제 조건을 확인합니다.
- 폰트·이미지·아이콘의 출처와 사용 조건을 확인합니다.
- 장애가 생기면 강사가 준비한 예제 저장소와 웹 화면 시연으로 이어갑니다.

## 완료 확인

- `git status`로 변경 상태를 확인했다.
- 에이전트 변경을 브라우저와 diff에서 확인했다.
- 파일을 커밋하고 GitHub에 push했다.
- GitHub 저장소와 Pages 결과를 열어 보았다.
- 작업 폴더·스테이징·커밋·원격 저장소의 차이를 설명했다.
